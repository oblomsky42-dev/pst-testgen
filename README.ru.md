# pst-testgen

*[English version](README.md)*

Создаёт PST-файлы Outlook с заранее известным правильным ответом — дата
доставки каждого письма с точностью до секунды, количество писем по годам и
месяцам, какие письма перенесены в «Удалённые», а какие стёрты окончательно —
и записывает этот ответ в манифест рядом с PST.

Инструментам, которые читают почтовые архивы — криминалистическим сканерам,
обработке в eDiscovery, парсерам на базе libpff, — нужен эталон для проверки.
У реальных почтовых ящиков его нет, а у публичных наборов вроде Enron нет
ключа ответов по датам и удалениям. pst-testgen делает PST, у которых он есть.

Проект появился для проверки
[email-date-range](https://github.com/oblomsky42-dev/email-date-range): его CI
сверяет каждое письмо PST от pst-testgen с манифестом.

## Требования

- Windows с классическим Outlook (2016 и новее; разработано на Outlook 2024).
  У «нового Outlook» нет COM-интерфейса, с ним не работает.
- Python 3.10+ и pywin32 (ставится вместе с пакетом).

Основной почтовый ящик не затрагивается. Новый PST подключается к профилю
Outlook по умолчанию на время работы и в конце отключается; если Outlook
запустил сам генератор, он его и закрывает — Outlook держит PST
заблокированным, пока его процесс жив.

## Установка

```bash
pip install git+https://github.com/oblomsky42-dev/pst-testgen
```

или возьмите `pst_testgen.exe` на странице
[Releases](https://github.com/oblomsky42-dev/pst-testgen/releases) (Outlook на
машине всё равно нужен).

## Использование

```bash
pst-testgen --out C:\test\t.pst --count 2000 --delete-pct 10 --delete-mode both
pst-testgen --out D:\test\big.pst --target-gb 5 --attach-mb 5 --attach-every 50
```

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `--out` | — | новый PST; файла ещё не должно быть |
| `--count N` | — | ровно N писем; без него PST заполняется до `--target-gb` |
| `--target-gb` | 1 | целевой размер файла |
| `--start-year`, `--end-year` | 2015, 2025 | диапазон дат; по годам число писем растёт и спадает |
| `--seed` | 1337 | тот же seed → те же даты, темы, отправители и удаления |
| `--attach-every`, `--attach-mb` | 50, 5 | вложение из случайных байтов у каждого N-го письма (0 МБ — без вложений) |
| `--body-kb` | 8 | балласт в теле письма |
| `--delete-pct` | 0 | доля писем, удаляемых после генерации |
| `--delete-mode` | both | `soft` — в «Удалённые», `hard` — окончательно (Shift+Delete), `both` — поровну |

Каждое письмо попадает в папку `TestMessages` и получает:

- тему `[ГГГГ-ММ-ДД] Test message N from <отправитель>` — дата в теме позволяет
  сверять вывод инструмента письмо за письмом;
- время доставки и отправки, равное этой дате, в UTC, до секунды;
- состояние «получено и прочитано» (не черновик), отправителя и получателя из
  фиксированного списка адресов вида `example.com` и Message-ID
  `<test-SEED-N@pst-testgen.example>`.

## Манифест

`<имя>_expected_manifest.json` (плюс сводка по годам в `.csv`):

| Ключ | Содержание |
|---|---|
| `schema_version` | `1` |
| `generator`, `generated_utc`, `seed`, `parameters` | как сделан файл |
| `pst_file` | имя PST — никогда не полный путь, чтобы манифестом можно было делиться |
| `total_messages_created`, `by_year_all_created` | всё, что записано |
| `expected.plain_scan` | `total_messages`, `by_year`, `by_month` («ГГГГ-ММ») — что должен показать скан дерева папок: живые и мягко удалённые письма |
| `expected.recover_scan` | `max_total_messages`, `max_additional_recovered` — верхняя граница для инструмента, читающего осиротевшие узлы (см. ниже) |
| `deletions` | счётчики и списки `soft_deleted_items` и `hard_deleted_items` с `subject`, `date` и `message_id` |

## Удаления и что от них остаётся

Мягкое удаление переносит письмо в «Удалённые»: оно остаётся в дереве папок,
и любой инструмент обязан его видеть. Жёсткое — стирает его и оттуда, как
Shift+Delete.

Что останется от стёртого письма, решает программа, которая пишет PST. Outlook
2016 и новее сразу убирает его из индексов PST. В проверке на Outlook 2024
1 800 стёртых писем не оставили ни осиротевших узлов, ни того, что смог бы
восстановить `pffexport -m recovered`. Поэтому манифест считает набор жёстко
удалённых верхней границей для восстановления, а не целью: инструмент, который
«восстановил» письмо не из `hard_deleted_items`, ошибается; инструмент, который
не восстановил ни одного, вполне может быть прав.

## Почему Extended MAPI

Очевидный путь — создать `MailItem` через объектную модель Outlook и
проставить `PR_MESSAGE_DELIVERY_TIME` через `PropertyAccessor` — не работает:
при сохранении нового элемента Outlook сбрасывает время доставки на «сейчас»,
независимо от того, задано ли свойство до первого сохранения или после, у
`MailItem` или у `PostItem`. Запись молча игнорируется.

pst-testgen использует объектную модель Outlook только чтобы создать PST и
папку и чтобы удалять. Сами письма пишутся через Extended MAPI (`win32com.mapi`
из pywin32): `IMAPIFolder::CreateMessage`, `SetProps` с временем доставки и
отправки, `PR_MESSAGE_FLAGS = MSGFLAG_READ`, таблица получателей через
`ModifyRecipients`, затем `SaveChanges`. MAPI сохраняет все значения как
заданы. Первое письмо после сохранения перечитывается, и если время доставки
не совпало до секунды, генерация останавливается: тестовый PST с неверными
датами хуже, чем никакой.

## Проверка

PST на 400, 2 000 и 3 000 писем, созданные на Outlook 2024, прочитаны libpff
(через email-date-range) и совпали с манифестами точно: итоги, разбивка по
годам и месяцам, время и Message-ID каждого письма, расположение каждого мягко
удалённого письма. Файл на 400 писем лежит в CI email-date-range как фикстура —
после проверки на персональные данные: каждое свойство, до которого
дотягивается libpff, сам файл и файл после снятия «перестановочного»
шифрования PST проверены на имя пользователя, компьютера, учётные записи и
пути машины-генератора, с положительным контролем, что поиск находит то, что в
файле есть.

Модульные тесты (план, выбор удалений, манифест, проверка аргументов) идут в
CI на Windows; часть с Outlook там не запустить, она проверяется вручную.

## Ограничения

- Только Windows и классический Outlook.
- Размер файла для `--target-gb` проверяется каждые 500 писем, так что
  результат немного больше заданного.
- Не сжимайте PST и не давайте Outlook проводить над ним обслуживание — и то и
  другое переписывает файл, и манифест перестаёт ему соответствовать.
